# FastHtmlParser на C++

[![CI](https://github.com/sanblch/fasthtmlparser-cpp/actions/workflows/ci.yml/badge.svg)](https://github.com/sanblch/fasthtmlparser-cpp/actions/workflows/ci.yml)

C++-порт библиотеки [z3l.FastHtmlParser](https://github.com/romanti3172/z3l.FastHtmlParser)
из статьи «[Какой язык быстрее? Сравнил 8 языков на одной задаче](https://habr.com/ru/articles/1109410/)».

Библиотека строит не DOM-дерево, а **плоский список тегов** — пары смещений в исходной строке.
Парсинг выполняется один раз, дальше документ доступен только на чтение. Есть три способа
поиска: свой Find API, CSS-селекторы и XPath 1.0, плюс декодирование всех 2125 именованных
HTML-сущностей и правила HTML5 о необязательных закрывающих тегах.

Порт повторяет архитектуру и поведение оригинального C#-кода: те же структуры данных, тот же
двухпроходный разбор (быстрый проход + повторное сканирование участков с необязательными
закрывающими тегами), те же CSS- и XPath-движки.

Та же библиотека портирована и на другие языки: оригинал на
[C#](https://github.com/romanti3172/z3l.FastHtmlParser) и
[Rust](https://github.com/romanti3172/fasthtmlparser-rs); сравнение языков — в статье.

## Сборка

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build          # или ./build/fh_tests fixtures tests/data
./build/fh_bench fixtures
```

Нужен компилятор с C++20 (`std::string_view`, `std::variant`, `std::to_chars` для `double`).
Проверено на g++ 15.2 (Linux), clang 21.1 (Linux) и MSVC 19.51 (Visual Studio 2026).
Внешних зависимостей нет.

## Быстрый старт

```cpp
#include <fh/fasthtmlparser.hpp>

fh::Document doc(html, "https://books.toscrape.com/");

// Самый быстрый вариант: без копирования текста. `html` должен пережить документ
// (как &str в Rust); документ не владеет строкой и не изменяет её.
fh::Document view = fh::Document::parse_borrowed(html);

// Find API
for (const fh::Tag& pod : doc.find_all(fh::TagQuery(fh::HtmlTag::Article).with_class("product_pod"))) {
    std::string title = pod.find(fh::TagQuery(fh::HtmlTag::H3))->find(fh::TagQuery(fh::HtmlTag::A))
                           ->attribute(fh::Attr::Title);
    std::string price = pod.find(fh::TagQuery(fh::HtmlTag::P).with_class("price_color"))->text();
}

// CSS
static const fh::CssQuery Price = fh::CssQuery::compile("p.price_color");
for (const fh::Tag& price : doc.css(Price)) { /* ... */ }

// XPath
static const fh::XPathQuery Pods =
    fh::XPathQuery::compile("//article[contains(concat(' ', @class, ' '), ' product_pod ')]");
for (const fh::Tag& pod : doc.xpath(Pods)) {
    std::string title = *pod.xpath_value(".//h3/a/@title");
}
```

Строковые перегрузки (`doc.css("div.card")`, `doc.xpath("//a/@href")`) компилируют селектор
лениво и кешируют его в общем кеше процесса, как в оригинале; скомпилированные `CssQuery` /
`XPathQuery` выгоднее держать в `static` и переиспользовать.

## Соответствие API

| Оригинал (C#)          | Порт (C++)                                        |
|---|---|
| `HtmlParser`           | `fh::Document`                                    |
| `ParserTag`            | `fh::Tag` (указатель на документ + индекс)        |
| `HtmlTag` / `HtmlAttribute` | `fh::HtmlTag` / `fh::Attr`                   |
| `Find` / `FindAll`     | `find` / `find_all` + `TagQuery`                  |
| `FindByNameClass(...)` | `find_by_name_class(...)`, `find_all_by_name_class(...)` |
| `Text()`, `Body()`, `Source()`, `FullSource()` | `text()`, `body()`, `source()`, `full_source()` |
| `AttributeByName`, `AttributeHref` | `attribute(...)`, `attribute_href()`   |
| `Css` / `CssFirst` / `IsCss` | `css` / `css_first` / `is_css`              |
| `XPath` / `XPathValue` / `XPathValues` | `xpath` / `xpath_value` / `xpath_values` |
| `CssQuery` / `XPathQuery` | `fh::CssQuery` / `fh::XPathQuery`              |
| `HtmlDecodeCore.HtmlDecode` | `fh::html_decode`                            |
| `HtmlToTextCore.ClearTags` | `fh::clear_tags`                              |

`Document` нельзя копировать и перемещать: `Tag` хранит указатель на документ. Создавайте его
на месте (`fh::Document doc(html);`). По умолчанию документ копирует исходник; если текст уже
в памяти и переживёт документ, `Document::parse_borrowed(html)` убирает копирование (ровно
семантика Rust `&str` и C# `string`), а `parse_owned(std::string)` забирает строку без копии. Документ доступен только на чтение после конструктора;
лениво строимое дерево для CSS-комбинаторов защищено `std::once_flag`.

## Что портировано

- `ParsingCore` — построение плоского списка тегов, быстрый проход и повторное сканирование
  (`Repair`) с правилами HTML5 (`li`, `dt/dd`, `td/th/tr`, `tbody/thead/tfoot`, `option`,
  `optgroup`, закрытие `<p>` блочными элементами), ограничение глубины 512, бюджет повторного
  сканирования, комментарии, `script/style/textarea/title/...` как raw text, XML-режим.
- Атрибуты читаются лениво из исходной строки (`AttributeScanner`), без объектов на атрибут.
- `HtmlDecodeCore` + таблица 2125 сущностей (включая 106 legacy-имён без `;`, числовые ссылки,
  замены 0x80–0x9F по Windows-1252) — таблица сгенерирована из оригинального C#-файла.
- `HtmlToTextCore`: удаление тегов и невидимого содержимого, схлопывание пробелов, декодирование
  сущностей; `clear_tags_line_breaks` — текст с переносами строк.
- CSS: типы, `*`, `#id`, `.class`, все атрибутные операторы с флагами `i`/`s`, комбинаторы
  ` `, `>`, `+`, `~`, списки, псевдоклассы `:first-child`, `:nth-child(An+B of S)`,
  `:not()`, `:is()`, `:where()`, `:has()`, `:empty`, `:root`, `:scope`, формы, ссылки,
  `:contains("...")`, CSS-escape-последовательности.
- XPath 1.0: все оси, кроме namespace; предикаты, `|`, операторы, функции ядра, `ends-with()`,
  `lower-case()`, `upper-case()`; строковые значения элементов через `Text()`.
- Упрощённое разрешение относительных ссылок (`attribute_href`/`attribute_src`).

## Сверка с оригиналом

Порт проверялся дифференциально против C#-библиотеки на тех же данных:

1. **Разбор.** 12 страниц из `fixtures` (плюс синтетические случаи в тестах), 3849 тегов.
   Совпадают имена тегов, порядок, глубина, `InnerStart` и `Text()` — все строки. Смещения
   (`Start`/`End`/`InnerStart`/`InnerEnd`) отличаются только потому, что C# считает позиции в
   UTF-16 code units, а порт — в байтах UTF-8; проверено, что каждое смещение пересчитывается
   в байтовое ровно (страницы с `£`, `“”`, `❤`).
2. **Поиск.** 97 CSS-селекторов и 66 XPath-выражений из оригинального набора тестов дают
   одинаковые id в одинаковом порядке; 75 выражений `XPathValue` — одинаковые значения.
   Эталон `tests/data/expected_queries.txt` сгенерирован C#-библиотекой
   (`tools/parity`), проверка входит в `fh_tests`.
3. **Нестандартные случаи.** Отдельно сверялись таблицы без `</td>`/`</tr>`, вложенные списки,
   обрезанные документы, комментарии `<!-->`, `<script>` с `</scriptx>`, CDATA, условные
   комментарии, BOM, CRLF, кастомные теги (`<my-widget>` против `</MyWidget>`), атрибуты
   с `<`/`>` внутри кавычек: 679 строк разбора совпали по имени, глубине и тексту.

## Бенчмарки

Та же задача и тот же корпус, что в статье: разбор страниц и скрапинг
books.toscrape.com (20 книг: название, цена, рейтинг) и quotes.toscrape.com
(10 цитат: текст, автор, теги) через Find, CSS и XPath. Методика повторяет бенчмарк
Rust-порта: прогрев с удвоением батча до 100 мс, затем пять батчей по 5× итераций,
в таблицах — медиана на вызов.

C++ умеет и то, и другое: `parse_borrowed` не копирует исходник (ровно как C# и Rust),
`Document(html)` копирует его, `parse_owned` забирает готовый `std::string`. В таблицах
C++ меряется через `parse_borrowed` — в том же режиме, что Rust и C#; цена копирования
показана отдельным столбцом в таблицах разбора.

Замеры:

- **Эта машина, Linux** — Intel Core i7-11800H (8 ядер / 16 потоков), Ubuntu 26.04,
  g++ 15.2 (`-O3`), clang 21.1.8; rustc 1.98.1 — локальная сборка Rust-порта; по 5 прогонов.
- **Эта машина, Windows** — гость VirtualBox на том же хосте, Windows 10, MSVC 19.51
  (Visual Studio 2026, `Release`); 5 прогонов. Внимание: в этой сессии VM работала примерно
  на 35–40% медленнее, чем в предыдущей, причём просадка одинакова и у `quotes`, где крупных
  аллокаций почти нет. Абсолютные Windows-числа C++ поэтому сравнимы только внутри сессии
  и по порядку величины; соотношение API и картина (XPath дороже) те же, что на Linux.
- **Статья** — Ryzen 7 3800X, Ubuntu 26.04 в Docker и Windows 10 LTSC в KVM. Числа статьи
  получены на другой машине, их стоит сравнивать с нашими с поправкой на железо.

### Как читать

- На одной и той же машине C++-порт и Rust-порт неразличимы: books 42.5 против 41.2 µs,
  ×10 434 против 423 µs, скрапинг Find/CSS/XPath 55/60/88 против 54/56/83 µs. При этом
  Rust-бенчмарк копирует исходник, а C++ заимствует; остаток разницы (1–6%) — уже детали
  реализации, а не языка.
- Разрыв на ×10 был не «языковым»: он исчез, когда массивы парсера (`tags_`, `states_`)
  переехали в thread-local scratch и перестали выделяться и обнуляться на каждый документ.
  Проверялись и другие гипотезы: `memchr3`/SSE2 внутри тега оказался медленнее штатного
  `find_first_of` (короткие участки), а предварительное построение `tags()` на разбор не влияло.
- Сравнение со статьёй корректно только по порядку величин: там Ryzen 7 3800X, здесь
  i7-11800H, а Windows-числа сняты в VirtualBox. Тем не менее C++ уверенно попадает в первую
  группу языков на разборе и в число лучших на скрапинге.

## Отличия от оригинала

- **Кодировка.** Исходник рассматривается как UTF-8-байты (в C# — UTF-16 code units), поэтому
  позиции — байтовые смещения, а декодированные сущности записываются в UTF-8. Для ASCII-страниц
  поведение идентично.
- `text_line_breaks()` соединяет строки `\n` (в оригинале `Environment.NewLine`).
- Функции, зависящие от Unicode-свойств (`char.IsWhiteSpace` для не-ASCII, регистронезависимые
  сравнения не-ASCII), работают по ASCII.
- Разрешение относительных ссылок — упрощённый RFC 3986 без полной семантики `System.Uri`.
- Реализовано подмножество «шорткатов» (`find_by_name`, `find_by_id`, `find_by_name_class`,
  `find_all_by_name_class`); полный набор тривиально добавляется поверх `TagQuery`.
- Нет `IDisposable`/пулов памяти. По умолчанию документ владеет копией исходника; чтобы не
  копировать, есть `parse_borrowed` (текст переживает документ) и `parse_owned` (передача
  `std::string`). В C# и Rust такого выбора нет — они всегда заимствуют строку.

## Структура

```
include/fh/fasthtmlparser.hpp   публичный API
include/fh/generated_names.hpp  enum HtmlTag/Attr + имена (сгенерировано из C#)

src/parse.cpp                   ParsingCore: плоский список тегов, правила HTML5
src/document.cpp                Document, Tag, TagQuery, атрибуты, поиск
src/text.cpp                    HTML → текст, комментарии, raw text
src/decode.cpp                  декодирование сущностей
src/tables.cpp                  поиск имён тегов/атрибутов
src/css.cpp                     CSS-компилятор и матчер, дерево сиблингов
src/xpath.cpp                   XPath 1.0: компилятор, выражения, обход

tools/gen_tables.py             генератор таблиц из исходников C#
tools/parity/                   C#-утилита для эталона tests/data/expected_queries.txt
bench/main.cpp                  бенчмарки
tests/main.cpp                  тесты
fixtures/, tests/data/          страницы и данные для тестов
```
